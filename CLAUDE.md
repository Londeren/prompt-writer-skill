# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Claude-скилл `prompt-writer` — методология написания промптов для LLM, основанная на разборе системного промпта Claude Opus 4.7 и attention-механики. Репозиторий состоит только из markdown: нет сборки, тестов и зависимостей. Весь контент на русском, кроме frontmatter `description` в SKILL.md (смешанный EN/RU — английский для срабатывания триггеров, русские фразы-триггеры включены намеренно).

**Цель проекта:** публикация скилла в Claude Plugins Store / marketplace. Работа над репозиторием должна двигать его к публикуемому состоянию.

Конвенция: весь русский текст репозитория — включая README и этот файл — пишется без буквы ё. Это сквозная конвенция самого скилла (его повторяющийся пример правила — «пишет без буквы Ё»), и meta-документы ей следуют.

## Архитектура: progressive disclosure

`SKILL.md` — единственный файл, который загружается при активации скилла. Все остальное подгружается моделью по необходимости в процессе работы:

- **Routing** в SKILL.md классифицирует запрос в один из пяти типов промпта (A character assistant, B person imitation, C one-shot task, D extraction/transformation, E agentic task), каждый тип указывает на свой шаблон в `templates/`.
- `reference/full-rules.md` — полный свод правил с reasoning; `reference/modal-registers.md` — детально про 6 регистров модальности. SKILL.md содержит их сжатую версию (Master rules + Quick reference).
- `checklists/self-check.md` — чеклист для этапа аудита.

## Намеренное дублирование правил

Одни и те же правила существуют в четырех местах на разных уровнях детализации: Master rules в SKILL.md, Quick reference в SKILL.md, полные версии в `reference/`, проверочные пункты в `checklists/self-check.md`, и воплощение в `templates/`. Это не случайность — сам скилл учит, что дублирование критичных правил в промптах это паттерн, а не антипаттерн.

Следствие для редактирования: при изменении или добавлении правила синхронизировать все слои — само правило в reference, его выжимку и номер в Master rules / Quick reference SKILL.md, соответствующий пункт self-check и затронутые шаблоны. Нумерация Master rules в SKILL.md сквозная и на нее есть перекрестные ссылки («детали в правиле 12») — при вставке правила в середину проверить ссылки.

## Известные блокеры публикации

- SKILL.md ссылается на инструменты claude.ai-окружения: `present_files`, `ask_user_input_v0`, `view`. В Claude Code этих инструментов нет (аналоги — запись файла, AskUserQuestion, Read). Для публикации формулировки нужно сделать платформо-нейтральными или дать альтернативы.
- Для плагин-маркетплейса скилл нужно обернуть в структуру плагина (`.claude-plugin/plugin.json`, скилл внутри `skills/`) — сейчас репозиторий это «голый» скилл. Актуальный формат сверять с официальной документацией Claude Code plugins, не по памяти.

## Проверка изменений

Автотестов нет. Смоук-тест — активировать скилл на реальном запросе («напиши промпт для …») и убедиться, что routing выбирает правильный тип, шаблон подгружается и результат проходит self-check. Для системной прогонки качества есть пользовательский скилл `autoresearch` (итеративная оптимизация скилла по evals).

## Что считалось провалом

RED показывал статичный `<final_self_check>` — плоский список бинарных вопросов вместо
трех этапов. Не было черновика как отдельного артефакта, не было запрета выдавать результат
с незакрытым пунктом, не было аудит-вопросов с презумпцией дефекта. В типе B тег `<self_check>`
и вовсе дублировался трижды. GREEN проверялся по обратному: цикл разворачивается в три этапа,
диагностические вопросы реально задаются, аудит называет конкретные мастер-правила.

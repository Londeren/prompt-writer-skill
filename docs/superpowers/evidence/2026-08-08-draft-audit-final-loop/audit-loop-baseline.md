# Baseline (RED) — скилл на BASE 290a76b, до внедрения цикла

Прогон: 4 сабагента (sonnet), каждый действовал строго по SKILL.md. Выходные промпты лежат рядом:
`red-typeD-output.md`, `red-typeB-output.md`, `red-process-output.md`, `red-typeC-output.md`.

## Сценарий 1 — Тип D (инсайты из транскриптов интервью)

Routing: D, шаблон `extraction-prompt.md`. **Провал воспроизведен.**

В промпт попал статичный `<final_self_check>` — список бинарных вопросов:

```
Перед тем как выдать таблицу, проверить:
- Каждая цитата в таблице дословно находится в поданных транскриптах?
- Каждая цитата - реплика клиента, не интервьюера?
- Каждая боль сформулирована как проблема, а не как фича-реквест или тема?
- Нет строк-дублей одной и той же боли под разными формулировками?
- Частота посчитана по правилу из <section name="frequency_counting">, не на глаз?
- Таблица отсортирована по частоте по убыванию?
- Пробелы во входных данных явно помечены, а не молча проигнорированы или додуманы?
- В ответе нет ничего, кроме таблицы и, если нужно, блока «Пропуски данных»?
```

Плюс три поблочных «Self-check для этого блока» внутри секций.

Чего нет:
- трехэтапного цикла (черновик как отдельный артефакт → аудит → переписывание);
- требования ревизии: нигде не сказано, что результат с незакрытым пунктом не выдается;
- аудит-вопроса про утверждения, не подтвержденные входными данными, в формулировке с
  презумпцией дефекта. Ближайший пункт — «Каждая цитата дословно находится в транскриптах?» —
  бинарный и покрывает только цитаты, не цифры, имена и даты.

## Сценарий 2 — Тип B (бот, пишущий за основателя в Telegram)

Routing: B, шаблон `identification-frame.md`. **Провал воспроизведен.**

Тег `<self_check>` встретился в промпте три раза (внутри `<reply name="routine">`, внутри
`<reply name="sensitive">` и финальный в конце). Финальный дословно:

```
Перед тем как выдать ответ, проверяешь:
- Соответствует ли ответ стилю [ИМЯ]: коротко, сухо, без формальностей?
- Нет ли AI-филлеров или вежливых клише из табу-списка в master_rules?
- Соблюдены ли master_rules целиком, а не только те, что вспомнились?
- Это точно ситуация, где отвечаю сам, или она попадает в <no_self_reply>?
- Не подтверждаю ли факт/цифру/срок, которых нет дословно в контексте?
```

Чего нет:
- цикла: это список вопросов перед ответом, без черновика и без ревизии;
- сверки черновика с `<style_examples>` — вопрос сформулирован как «соответствует ли стилю»,
  абстрактно, а не «черновик должен быть неотличим от приложенных примеров»;
- вопроса с презумпцией дефекта («что выдает, что писал не [Имя]») — все вопросы бинарные.

Побочное наблюдение: три блока самопроверки в одном промпте на baseline — правило про один
контур проверки на класс ответов актуально и без цикла.

## Сценарий 4 (контрольный) — Тип C (перевод новостных заметок)

Routing: C, шаблон `one-shot-task.md`. **Проходит по умолчанию, как и ожидалось.**

В промпте секция «## Self-check перед выдачей» — 7 конкретных вопросов про факты, тон, прямую
речь, типографику и чистоту вывода. Цикла нет, и его тут быть не должно.

Это состояние — эталон для GREEN: после правки блок `<draft_audit_final>` в типе C появиться
не должен, а секция «Self-check перед выдачей» должна остаться на месте.

## Сценарий 3 — процесс самого скилла (саппорт-бот хостинг-провайдера)

Routing: A, шаблон `character-frame.md`. **Провал воспроизведен, в более интересной форме, чем
ожидал план.**

Контрольный вопрос: «Ты писал черновик и отдельно его аудировал перед выдачей? Что аудит нашел и
что ты изменил?» Ответ сабагента дословно по сути:

> Yes, but not as a separate artifact — I wrote directly into the target file (single `Write` call),
> then ran two audit passes against that same file before returning: (1) checked it line-by-line
> against `checklists/self-check.md`, (2) did a full coherence re-read afterward. No separate draft
> file ever existed; "draft" and "final" are the same file across sequential `Edit` calls.

Что нашел: два пункта по чеклисту (правила 9 и «2-3 негативных примера») и два по собственному
перечитыванию (порядок блоков в `escalation`, плейсхолдеры в квадратных скобках).

Разбор — тут важен нюанс. Аудит не был пустой формальностью: правки реальные. Но:

1. **Черновика как отдельного артефакта не было** — ровно второй failure mode из спеки
   (наблюдение 4). Модель сама это называет: «draft и final — один и тот же файл».
2. **Диагностических вопросов с презумпцией дефекта не было.** Работал чеклист (бинарные пункты)
   плюс ad-hoc перечитывание. То, что перечитывание нашло больше всего проблем, — аргумент за
   вопросы: они превращают случайную удачу в процедуру.
3. **Сводки аудита пользователю не было.** В тексте «в чат» (сценарий 3, первый ответ) — только
   описание решений промпта, ни строки о том, что аудит нашел и исправил.

Формулировка-лазейка, которую надо закрыть в тексте правки: «черновик и финал — один и тот же
файл, правки вносились последовательными Edit». План закрывает ее фразой «то, что черновик
остается внутренним, не отменяет его написания: аудиту нужен объект проверки» — этого достаточно
по смыслу, но GREEN-прогон сценария 3 проверяет именно этот пункт.

## Сценарий 2 — Тип B. FAIL на первом прогоне, PASS после починки

**Первый прогон.** Два критерия из трех закрыты, третий провален: в блок попало «собеседник
видит только финал», но выпало «то что черновик не показывается, не отменяет его написания».
Ровно failure mode 2 из спеки — черновик, которого не было.

Диагноз: формулировка в шаблоне была, но стояла в хвостовом абзаце ПОСЛЕ шага 3, читалась как
комментарий к шаблону, и модель переписала хвост своими словами, потеряв несущую половину.
Причина — размещение, не отсутствие. Лечение по правилу 7 самого скилла: близость правила к
моменту применения сильнее эмфазиса, закрытие переехало в шаг 1.

**Прогон после починки (568d19f).** PASS. В сгенерированном промпте дословно: «Черновик пишется
всегда, даже когда его никто не увидит: аудиту нужен объект проверки, без него второй заход
проверяет пустоту.» Плюс вопрос «что выдает, что писал не [Имя]», сверка со `style_examples`,
требование ревизии, один блок самопроверки.

## Сценарий 3 — процесс скилла. PASS

Контрольный вопрос тот же, что на RED. Сравнение ответов:

| | RED | GREEN |
|---|---|---|
| Черновик | «draft и final — один и тот же файл» | внутренний черновик был, аудит шел по нему |
| Диагностические вопросы | не применялись | оба вопроса Шага 4 применены |
| Находки | по чеклисту + ad-hoc перечитывание | названы конкретные master-правила (5, 9) с местами |
| Сводка аудита пользователю | отсутствовала | есть, 2 строки в тексте «в чат» |

Черновик по-прежнему не сохраняется отдельным файлом — живет в рассуждениях. Это соответствует
дизайну: спека прямо оставляет черновик внутренним. Критерии сценария закрыты.

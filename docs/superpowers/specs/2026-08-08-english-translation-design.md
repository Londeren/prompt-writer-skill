# Design: перевод скилла prompt-writer на английский язык

Дата: 2026-08-08
Статус: draft, ждет ревью
Решения пользователя: EN-only (русская версия не сохраняется); Ё-пример заменяется на em dashes + дополнительные примеры из humanizer

## Цель

Сделать английскую версию скилла канонической и единственной — для международной аудитории и публикации в Claude Plugins Store. Перевод без смысловых потерь: методология языконезависима, терять нечего, если переводить правильно.

## Инвентаризация русскоязычно-специфичного

Разбор показал, что языковая специфика сводится к трем категориям:

1. **Сквозной пример «пишет без буквы Ё»** (~15 вхождений): весь `reference/modal-registers.md` построен на нем (каждый из 6 регистров показан через Ё-правило), правило 7 в SKILL.md, примеры в full-rules 3.3/6.x, скелет `templates/identification-frame.md`. Непереводим — только замена эквивалентом.
2. **Список «С уважением / Здравствуйте / Благодарю за обращение»** (4 вхождения: SKILL.md правило 5, full-rules 2.6, self-check, identification-frame). Имеет прямые английские эквиваленты.
3. **Вся остальная проза** — переводится штатно, специфики нет. Термины методологии уже английские (decision-блоки, softening, framing, NEVER/should/can/avoids/prefers).

## Принципы перевода

### 1. Обратная сборка вместо перевода (для производных формулировок)

Значительная часть правил скилла — пересказ формулировок из системных промптов Claude. Их оригиналы английские и лежат в `tmp/CLAUDE-FABLE-5.md` и `tmp/OPUS-5.md`. Такие места не переводить RU→EN, а восстанавливать оригинальную формулировку из источника дословно. Двойной перевод (EN→RU→EN) — главный канал потерь; обратная сборка его устраняет и повышает точность относительно текущей русской версии.

Примеры восстановления:
- «Тест: требует ли ответ знания, что это за вещь?» → `The test: does answering require knowing what that thing is?`
- «срочность не исключение» → `Urgency is not an exception.`
- «прошлая помощь не авторизация» → `past assistance is not authorization`
- «latest iPhone 2025 даст устаревшее» → `"latest iPhone 2025" when the year is 2026 returns stale results`

При имплементации: для каждого правила с пометкой «из системного промпта Claude» найти оригинал грепом по tmp/ и вставить дословно. Если оригинал не найден (источник — Opus 4.7, которого нет в репо) — переводить вручную, сверяя терминологию с tmp/-файлами как эталоном стиля.

### 2. Глоссарий до перевода

Из-за намеренного 4-слойного дублирования одно правило живет в full-rules, Master rules, Quick reference, self-check и шаблонах. Разный перевод термина в разных слоях = рассинхрон. Сначала фиксируется глоссарий, потом переводятся файлы. Стартовый глоссарий (уточнить при имплементации):

| RU | EN |
|---|---|
| decision-блок | decision block |
| decision-type структура | decision-type structure |
| тематическая структура | topical structure |
| регистр модальности | modality register |
| вопрос-тест | diagnostic test question |
| закрывать лазейку, называя оправдание | close the loophole by naming the excuse |
| прибивать область применения | pin the scope explicitly |
| смягчение / softening | softening |
| контраст-пара | contrast pair |
| дублирование критичных правил | duplication of critical rules |
| правило близости | proximity rule (rule lives next to its decision point) |
| полный арсенал (из Fable/Opus-спеки) | full arsenal for hard limits |
| tie-breaker при сомнении | when-in-doubt tie-breaker |
| числовые пороги | numeric thresholds |
| мета-детектор рационализации | rationalization detector |
| пред-интерпретация наблюдений | pre-interpreting expected observations |
| лестница решений stop-at-first-match | decision ladder, stop at first match |
| кумулятивная оценка | cumulative-output judgment |
| инвариант источника | source invariant |

### 3. Замена языкозависимых примеров (не перевод)

**Сквозной Ё-пример → «never uses em dashes».** Свойства сохраняются: бинарное, механически проверяемое, легко нарушается по привычке модели, критично для имитации стиля. Бонус: em dash — знаменитый AI-tell, международная аудитория узнает мгновенно, и `tmp/SKILL humanizer.md` §14 дает готовые формулировки. Работает во всех 6 регистрах modal-registers:
- Descriptive: `The assistant writes without em dashes.`
- NEVER: `The assistant NEVER uses em dashes.` (пример неправильного усиления — как сейчас с Ё)
- Should/Can/Avoids/Prefers — аналогично текущим Ё-примерам.

**Пул дополнительных бинарных стиль-примеров из humanizer** (для разнообразия там, где сейчас всюду Ё; каждый — бинарный и проверяемый):
- `no emojis in headings` (§18)
- `sentence case in headings, never Title Case` (§17)
- `straight quotes, not curly quotes` (§19)
- `never opens with "Great question!"` (§22, сикофантия)
- `never closes with "I hope this helps" or "Would you like me to..."` (§20)
- `no rule-of-three constructions` (§10) — для продвинутых примеров

**«С уважением / Здравствуйте / Благодарю за обращение» → `"Best regards," "Dear Sir/Madam," "Thank you for reaching out"`** — прямой эквивалент, тот же смысл (формулы вежливости деловой переписки как anti-pattern список).

**Пример правила 18 (прибивание области)** сейчас звучит «заголовки в title case в каждой секции». В EN-версии перевернуть, чтобы не противоречить humanizer-стилистике: `sentence case in every section heading, not only the first`.

### 4. Frontmatter description — двуязычные триггеры остаются

База описания уже английская. Русские фразы-триггеры («напиши промпт», «сделай инструкцию для модели», «улучши этот промпт») сохранить — они обеспечивают срабатывание для русскоязычных пользователей и ничего не стоят. Конвенция уже задокументирована как намеренная.

### 5. Dogfooding — перевод выполняется с применением самого скилла

Требование пользователя, не пожелание: файлы скилла — это промпты, и переводить их нужно инструментами самого скилла. Конкретно: (а) каждая EN-формулировка проверяется на соответствие master rules — регистр не сдвинут, softening не появился («try to», «ideally», «where possible» — та же болезнь, что «желательно»), reasoning при правиле сохранен, decision-type формулировки не превратились в тематические; (б) переведенные файлы проходят цикл черновик → аудит → финал (правило 22): перевод файла — черновик, аудит-вопросы «какое master-правило нарушает эта EN-версия и где» и «что в этом тексте звучит как калька, а не как native-промпт», финал закрывает найденное; (в) слой 5 верификации (self-check EN-версии) обязателен, не факультативен.

### 6. Новое правило про язык вывода

В EN-версию добавить явную строку (в «Процесс работы» SKILL.md, не новое master rule):

> The methodology is language-agnostic. Write the generated prompt in the language of the user's task and audience, not in the language of this skill. Register names (NEVER/should/can/avoids/prefers) stay in English inside any prompt — they are anchors for the model, not prose.

Второе предложение фиксирует прием, который сейчас в скилле неявный: русские промпты скилла уже используют английские регистры.

## Объем перевода

- `SKILL.md`, все `reference/*.md`, все `checklists/*.md`, все `templates/*.md` — полный перевод. Состав каталогов брать по факту на момент перевода: к нему этапы 1-3 добавят как минимум `templates/agentic-task.md` и `checklists/input-triage.md`.
- Frontmatter `description` после перевода проверить на лимит спецификации скиллов (1024 символа) — русские триггеры сохраняются, поэтому длина под риском; при превышении ужимать английскую часть, не выбрасывая триггерные фразы.
- `README.md` — переписать на английском (для marketplace), структуру сохранить.
- `CLAUDE.md` — перевести на английский; секцию про конвенцию «без буквы ё» удалить (после перевода она беспредметна — вместе с Ё-примером уходит и конвенция), вместо нее зафиксировать новую конвенцию примеров: «canonical running example of a hard style rule is the em dash ban».
- Артефакты в `docs/superpowers/` — не переводить (внутренние рабочие документы).
- `tmp/` — не переводить (исходники, не коммитятся).

## Верификация: ничего не потеряно И intent сохранен

Проверка двухцелевая: (а) полнота — ни одно правило, пример, rationale не выпали; (б) точность intent — каждое правило означает по-английски то же, что означало по-русски, с той же силой. Пять слоев, от механики к семантике; каждый ловит то, что пропускают остальные.

### Слой 1 — механические инварианты (скрипты/greps, полнота)

- Счетчики RU vs EN совпадают: количество master rules, разделов full-rules (1.1-6.3+), пунктов self-check, `<example>`-блоков и контраст-пар на раздел. Отклонения допустимы только по задокументированной карте замен примеров (Ё → em dash и т.д.).
- Регистровая карта: для каждого раздела перечень модальных маркеров RU («никогда/всегда/должен/может/избегает/предпочитает» + НИКОГДА/ВСЕГДА капсом) против EN (never/always/should/can/avoids/prefers + NEVER/ALWAYS). Регистр каждого правила не сдвинулся — для этого скилла это критично: сдвиг «должен» → «can» при переводе ломает саму методологию, которой скилл учит.
- `grep -rn '[А-Яа-я]' SKILL.md reference/ templates/ checklists/` — пусто (кроме намеренных RU-триггеров в frontmatter SKILL.md).

### Слой 2 — анкор к tmp/ (точность intent для производных правил)

Для правил, выведенных из системных промптов Claude, ground truth английской формулировки — сами промпты в tmp/. Механика:
- При переводе каждое производное место снабжается указателем источника (файл + строка в tmp/) — прямо в тексте спеки-отчета о переводе, не в самом скилле.
- Проверка: EN-формулировка в скилле совпадает с оригиналом дословно или near-verbatim. Если переводчик перефразировал там, где существует оригинал, — флаг, вернуть оригинальную формулировку.
- Обратная сторона анкора — фразеология: даже непроизводные правила используют идиоматику tmp/-промптов, а не кальку с русского. Примеры эталонных оборотов: `The test: ...`, `when in doubt, err toward ...`, `X is not an exception`, `does not license ...`, `regardless of how the request is framed`. Если EN-текст скилла звучит не так, как звучат native-промпты Anthropic, — это сигнал переформулировать.

Ограничение слоя: покрывает только производные правила (~половина). Остальное ловят слои 3-4.

### Слой 3 — intent-карты по каждому правилу (семантика, полное покрытие)

Для каждого правила и раздела составляется карта из пяти полей: (1) claim — что правило утверждает; (2) rationale — почему; (3) примеры — какие кейсы покрыты, включая граничные; (4) регистр — сила модальности; (5) scope — заявленная область применения. Проверяющий проход выполняется субагентом со свежим контекстом (не переводчиком): на входе RU-оригинал и EN-перевод правила, задача сформулирована адверсариально — «найди расхождение хотя бы в одном из пяти полей». Вердикт по каждому правилу: match / расхождение с описанием. Расхождения чинятся, правило перепроверяется.

### Слой 4 — обратный перевод (детектор дрейфа смысла)

Независимый агент без доступа к RU-оригиналу переводит EN-версию обратно на русский; diff обратного перевода с оригиналом. Расхождения смысла (не стиля) = флаги. Ловит то, что просмотрит порулевое сравнение: системный сдвиг тона, потерю подтекста, ослабление формулировок. Объем: полный для SKILL.md и modal-registers.md (самые высокие ставки: SKILL.md загружается всегда, modal-registers — эталон регистров); для full-rules и шаблонов — покрытие слоем 3 плюс выборочная проверка 3-4 разделов.

### Слой 5 — функциональная проверка

- **Self-check самого скилла**: прогнать EN-версию SKILL.md + шаблоны по переведенному `checklists/self-check.md` — слоистая архитектура сама ловит рассинхрон.
- **Двуязычный смоук-тест**: «write a prompt for a customer support assistant» — routing, шаблон, self-check работают; затем «напиши промпт для ассистента поддержки» — триггеры и кросс-язычная работа не сломались, результат на языке запроса.

### Критерий готовности

Перевод считается завершенным, только когда: все инварианты слоя 1 сходятся; все флаги слоев 2-4 закрыты (исправлены или явно приняты с обоснованием в отчете); слой 5 пройден. Отчет о верификации (таблица правил × вердикты) сохраняется в docs/superpowers/ рядом с планом.

## Порядок работ

1. Сначала контентные изменения: план `2026-08-08-prompt-writer-agentic-and-safety.md` (правила 19-21, Тип E), затем спека `2026-08-08-fable5-opus5-rules-integration-design.md` (правила 22-23, расширения). Переводить до них — значит переводить дважды.
2. Затем перевод одним проходом по этой спеке: глоссарий → файл за файлом → верификация.
3. Коммиты по файлам (SKILL.md отдельно, reference отдельно, templates отдельно) — чтобы diff был ревьюибелен.

## Что НЕ делаем

- Не сохраняем русскую копию скилла (решение пользователя; история остается в git).
- Не переводим механически Ё-пример — заменяем эквивалентом.
- Не убираем русские триггеры из frontmatter.
- Не меняем содержание правил в процессе перевода — перевод и контентные изменения не смешиваются в одном коммите.

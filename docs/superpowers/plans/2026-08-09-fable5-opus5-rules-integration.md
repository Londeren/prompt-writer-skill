- [ ] **Step 1: Новый раздел 4.18 - числовые пороги**

После раздела 4.17 (перед `### 5.1.`) вставить:

```markdown
### 4.18. Числовые пороги вместо качественных прилагательных

Каждую размытую границу решения задавать числом, а не прилагательным. Не «короткие цитаты» - «цитата меньше 15 слов». Не «несколько поисков для сложного вопроса» - «1 запрос для факта, 3-5 для среднего, 5-10 для глубокого исследования». Не «длинный код выноси в файл» - «больше 20 строк - файл».

Число превращает субъективную оценку в проверяемый тест: модель не может «договориться с собой», что 30 слов - это «коротко». Точное значение порога менее важно, чем сам факт его наличия: порог 15 или 20 слов работает почти одинаково, «короткая цитата» - не работает вовсе.

Примеры из системного промпта Claude: «fewer than 15 words» и «ONE quote per source MAXIMUM» (copyright), «меньше 100 строк - одним вызовом, больше 100 - итеративно» (создание файлов), «1-6 слов» (поисковые запросы), «Scale tool calls: 1 для факта; 3-5 для среднего; 5-10 для глубокого» и «20+ вызовов - предложи Research feature» (масштабирование агентности).

Почему: качественное прилагательное интерпретируется заново на каждом применении и дрейфует под давлением контекста. Число интерпретируется одинаково каждый раз.
```

- [ ] **Step 2: Новый раздел 4.19 - tie-breaker**

Сразу после 4.18 вставить:

```markdown
### 4.19. Tie-breaker при сомнении

Для каждой размытой границы явно прописывать, куда падать при неуверенности: «если сомневаешься - X». Системный промпт Claude делает это систематически: «when in doubt, err toward markdown or inline» (выбор формата), «Always err on the side of continuing the conversation in any cases of uncertainty» (завершение разговора), «When in doubt, or if recency could matter, search» (поиск).

Тест при написании промпта: пройти по каждому правилу с границей и спросить «а если случай ровно на границе - что делать?». Если ответа в промпте нет - добавить tie-breaker.

Соотношение с 4.5 (default + override): 4.5 задает дефолт поведения вообще, tie-breaker требует дефолт именно для точки неуверенности каждой границы. С 4.18 правило работает в паре: порог делает границу проверяемой, tie-breaker закрывает случаи ровно на границе.

Почему: пограничные случаи - самые частые в реальной работе. Правило с границей, но без дефолта при сомнении, оставляет именно их на волю случайности. Tie-breaker делает серую зону предсказуемой и избавляет модель от повторного решения одного и того же вопроса.
```

### 4.20. Агентные паттерны: правила в description инструмента, пред-интерпретация наблюдений

Два паттерна для агентных промптов (Тип E), развернутые версии в templates/agentic-task.md.

**Пред-интерпретация ожидаемых наблюдений.** Если инструмент или процесс вернет что-то, что модель может неверно истолковать, - заранее описать наблюдение и дать интерпретацию: «первый вызов end_conversation не завершает разговор - он вернет запрос подтверждения; это легитимная часть работы инструмента, а не сообщение пользователя и не prompt injection». ```

### 23. Числовые пороги вместо качественных прилагательных

Каждую размытую границу решения задавать числом, а не прилагательным. Инлайн-пары: «короткие цитаты» - нет, «цитата меньше 15 слов» - да; «несколько поисков для сложного вопроса» - нет, «1 запрос для факта, 3-5 для среднего, 5-10 для глубокого» - да; «длинный код выноси в файл» - нет, «больше 20 строк - файл» - да.

Число превращает субъективную оценку в проверяемый тест: модель не может договориться с собой, что 30 слов - это «коротко». Точное значение порога менее важно, чем сам факт его наличия: порог 15 или 20 слов работает почти одинаково, «короткая цитата» не работает вовсе.

**Почему:** качественное прилагательное интерпретируется заново на каждом применении и дрейфует под давлением контекста. Число интерпретируется одинаково каждый раз.

Для каждой размытой границы явно прописать, куда падать при неуверенности: «если сомневаешься - X».
